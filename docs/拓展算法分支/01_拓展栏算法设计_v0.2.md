# 「拓展 / 智能拓展词典」算法设计 v0.2

> 版本：v0.2（扩展设计稿，暂不实现）
> 日期：2026-08-18
> 状态：研究阶段，待用户确认方向后再动工
> 相对 v0.1 的变化：定位从“词卡的一栏”升级为“以词为中心的智能拓展词典/插件”；模型选择改为可配置、不绑定厂商；补充了更多学术算法路径与“人性化”设计。

## 0. 定位（一句话）

以单个单词为中心，把「生僻含义 / 衍生表达 / 特殊搭配 / 习语俚语 / 词形变形漂移 / 词源同族」做一次**极致检索关联的“爆炸式”展开**，并用统一的知识模型组织起来。它不是第二本词典、不是无脑堆短语，也不是一次性问答，而是一个**可持久化、可跨语言、可插件分发**的词知识底座。

核心差异（用户认可的定性）：语言是人创造的，任何表达定向搜索都能搜到；我们的价值**不在“创造新表达”，而在“把已有表达以更人性化、更结构化的方式召回、融合、排序、语境化、个性化”**——并做成一个随时可用的插件，而不是背词时临时去搜。

## 1. 问题定义（升级版）

### 1.1 输入输出

- 输入：一个词（如 `give`、`mine`、`blast`），以及它的语言（目前英语）。
- 输出：围绕该词的“拓展卡片”，按类型分组的表达清单，每条含：表达、中文释义、例句、语境/语域标签、置信度、来源、关联词。

### 1.2 要覆盖的“拓展”维度（比 v0.1 更全）

| 维度 | 说明 | 示例 |
|------|------|------|
| 词形漂移 | 变形后语义/词性改变 | give → given（句首“鉴于”） |
| 习语/惯用语 | 整体义 ≠ 字面组合 | have a blast、make ends meet |
| 特殊搭配 | 高频固定、字面勉强可猜 | double-edged sword |
| 俚语/口语 | 非正式固定表达 | spill the beans |
| 短语动词 | 动词+小品词 | give up / give in / give away |
| 生僻义项 | 低频但重要的词义 | mine 作“地雷/矿藏/大量资源”之外的引申义 |
| 词源/同族 | 同源词、派生链、借词 | 支持多语言（先英语，后法语） |

### 1.3 负样本（不输出）

- 完全字面组合：`eat dinner`、`blue car`。
- 与现有“搭配/短语”列重复的普通表达。
- 语料不足、无法给出可信来源的“生造”表达。

边界判据仍是 **语义漂移 + 非组合性 + 固定性**，但 v0.2 把它从“二元判定”升级为“置信度分级”，更符合“人性化”目标（见 §7）。

## 2. 资源底座（开源可分发 + 本地可选增强）

### 2.1 开源可再分发（随项目发布）

- **DANTE**（lexicalcomputing/dante）：42k 词目 + 23k 多词表达 + 27k 习语，主底座。
- **ECDICT**（本地 77 万条）：词形/变体/短语兜底。
- **用户短语动词库** `reference_phrasal_verbs.json`（3217 条）：短语动词种子。
- **词源知识图谱**：Etytree（Wiktionary 交互式词源图）、unified-etymology-graph（2270 万关系 / 660 万词 / 5529 语言，CC-BY-SA）——用于词源/同族/多语言扩展。
- **WordNet**：词义、同义反义、上下位、派生词形。

### 2.2 本地可选增强（用户自备，不随开源发布）

- McGraw-Hill 习语包（22,209 条，个人/非商业许可）。
- 牛津/朗文/柯林斯等权威词典数据（用户自购/自备，运行时加载）。

## 3. 学术算法路径（多路径探索）

把“拓展”拆成几个子问题，每个子问题都有成熟学术路径可借鉴：

### 3.1 潜在习语表达（PIE）

- Haagsma et al. 2019《Casting a Wide Net》结论：**词典可靠，多词典合并显著提升召回**（解析抽取 F1 88%，合并后 >92%）。
- 借鉴：把多源表达库合并，用“潜在（potentially）”而非“确定”的立场做召回，这正是我们“置信度分级”的来源。

### 3.2 词义归纳与语义漂移（WSI / LSC）

- **Word Sense Induction（WSI）**：CoKE 用上下文知识嵌入归纳多义词义；超图模型（UOY）建模词共现的多维关系。
- **Lexical Semantic Change Detection（LSC）**：Periti & Tahmasebi 2024、Kutuzov et al. 的综述；用于捕捉“生僻/引申义”这类共时或历时的语义漂移。
- 借鉴：把“生僻义项”看成一个 WSI/LSC 子任务，用上下文聚类 + 词义向量识别低频义。

### 3.3 语义漂移 / 非组合性量化（对 MICE/CLCL 的轻量复用）

- 定义 `drift = 1 − cos_sim(emb(表达整体), emb(字面组合))`。
- 表达整体向量用句子模型（MiniLM/BGE），字面组合向量用成分词向量加权。
- drift 高 → 非字面 → 更像“拓展”。

### 3.4 搭配显著性统计量

- MI、T-score、LLR、Dice（公式见 §6.3），用于过滤透明组合、给固定性打分。

### 3.5 知识图谱 + 检索增强（GraphRAG 思路）

- 以“词”为实体，构建关系图：词义、同义反义、上下位、搭配、短语、词源同族、借词路径。
- 用 GraphRAG 的“局部检索 + 多跳推理”替代纯向量检索，回答“mine 有什么生僻搭配/引申义”这类需要关系推理的问题。
- 借鉴项目：Microsoft GraphRAG、ai-vocab-agent（词根知识图谱 + RAG）、dsh-knowledge（混合检索 + rerank）。

### 3.6 多语言可扩展

- 用词源知识图谱（unified-etymology-graph 覆盖 5529 语言）做同族/借词桥接；语言特定资源（法语 Wiktionary / 开放词典）作为该语言的底座。算法主体语言无关，只需替换“底座 + 词形还原器 + TTS”。

## 4. 总体流程（六阶段，比 v0.1 多一个“知识图谱层”）

```
0 词目归一 + 形态展开 + 语言识别
  ↓
1 统一表达库构建（多源合并 + 词源图谱）
  ↓
2 召回（倒排索引 + 图谱邻居）
  ↓
3 过滤（结构启发式 + 统计量）
  ↓
4 语义漂移 + 关系排序（向量 + 图谱）
  ↓
5 LLM 终判 + 置信度分级 + 生成（模型可配置）
```

### 阶段 0：词目归一 + 形态展开 + 语言识别

- 语言识别（先英语，预留法语），选择对应词形还原器。
- 生成词形集合：`give → {give, gives, gave, given, giving}`。

### 阶段 1：统一表达库 + 词源图谱

- 多源合并（DANTE + ECDICT + 短语库 + 词源图 + 可选增强包）。
- 条目对象统一含：`expr / lemma_keys / tags / source / zh / example / register / confidence`。
- 多源命中加权（呼应 PIE“多词典合并提升覆盖”）。

### 阶段 2：召回

- 倒排索引（lemma → expr）+ 词源图谱邻居（同族/派生/借词）。
- 高召回、宁多勿漏。

### 阶段 3：过滤

- 结构启发式（含介词/冠词锚点、词长 2–4、词性序列罕见度）。
- 统计量（MI/LLR/T-score/Dice）剔除透明组合。

### 阶段 4：语义漂移 + 关系排序

- 综合分 `score = α·drift + β·MI + γ·source_weight + δ·graph_salience`。
- 输出候选短名单（每词 ≤ 8–10 条）。

### 阶段 5：LLM 终判 + 置信度分级 + 生成

- 只对短名单调用 LLM，输出结构化 JSON：`zh / tag / example / example_zh / register / note / confidence`。
- 分级：`高可信（多源一致） / 中可信（单源+向量支持） / 待人工复核（LLM 推断但无词典来源）`。
- **模型可配置**：不绑定厂商，用户可填 Key、切换厂商/模型（与 KTRT 现有“设置”一致）。

## 5. 类型标签体系（两大类 + 小类）

- **大类 A · 语义衍生 / 抽象引申**：生僻意思导致“无厘头”或“抽象扩展词义”的衍生。
  - A1 生僻义 / 引申义（rare_sense）
  - A2 习语（idiom）
  - A3 俚语（slang）
  - A4 名词短语 / 特殊搭配（noun_phrase / special_colloc）
- **大类 B · 动词结构漂移**：词 + 小品词 / 词形变化导致，词和短语/变形完全不同。
  - B1 短语动词（phrasal_verb）—— 中文释义须区分「字面直译」与「真实含义」（turn → turn up：字面“向上转” vs 真实“出现 / 调大”）
  - B2 动词变形漂移（verb_form）—— give → given（句首“鉴于”）

每条拓展携带 `category(A/B) + sub_tag + register + confidence + source`。

边界：B 类不收普通固定介词搭配（如 satisfy with 这类字面可推），只收真正改变语义的短语动词/变形。原「词源/同族」移出“拓展”标签（同根词已有独立列，词源仅作多语言桥接）。

## 6. 统计量公式（阶段 3 用）

设 x、y 为表达中的两个成分词，N 为总 token 数，f(x)、f(y) 为词频，f(x,y) 为共现频：

- 互信息：`MI(x,y) = log2 [ f(x,y)·N / (f(x)·f(y)) ]`
- T-score：`T(x,y) ≈ [ f(x,y) − f(x)f(y)/N ] / √f(x,y)`
- 对数似然比 LLR：G² 检验共现是否显著非独立
- Dice：`Dice(x,y) = 2·f(x,y) / (f(x)+f(y))`

## 7. “人性化”设计（相对 v0.1 新增）

1. **置信度分级**而非硬性二元：给用户“这条有多可信”，而不是“有/没有”。
2. **可解释**：每条拓展标注来源（哪本词典/哪个图谱边/哪次 LLM 推断）。
3. **语境化**：不只给表达，还给例句、语域（正式/口语/俚语）、使用提示。
4. **个性化**：结合用户的“熟悉/收藏/造句”反馈，调整排序与推荐。
5. **增量、可纠错**：用户可手动增删拓展、修正释义，反哺模型。
6. **离线优先**：底座/图谱/向量本地化，联网只在“可选增强/实时词典查询”时才需要。

## 8. 模型分工（修正版）

- 本阶段**不绑定具体模型厂商，也不默认 DeepSeek**。
- 原则：把任务分成“需要强推理/质量”的（算法开发、终判生成）与“机械批处理/流水线”的（词表翻译、Excel、语料预处理）。
- 落地时，模型厂商/模型作为**可配置项**由用户填写（与现有“设置”一致），未来可自由切换 ds/db/gpt/gemini/claude/qw/grok 等。

## 9. 呈现形态（插件化）

- 形态：桌面（现有 KTRT 可视为第一形态）→ 浏览器插件（划词触发“拓展爆炸”）→ 移动端/系统级词典插件（填补 iOS 系统词典的缺口）。
- 架构分层：**算法/知识底座（语言无关、可复用）** 与 **前端适配层（各平台插件）** 解耦。

## 11. 实施路线（草稿，暂不动工）

- P0：统一表达库 + 词源图谱 + 倒排索引（离线脚本）。
