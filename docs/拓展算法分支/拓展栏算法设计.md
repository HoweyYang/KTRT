# KTRT「拓展」栏：候选衍生表达匹配与生成算法设计

> 版本：v0.1（设计稿，待评审）
> 日期：2026-08-18
> 作者：Howey / Howisey-Joy
> 目标：为 KTRT 词库新增「拓展」一栏，自动判断某个词是否存在「常见但脱离本意的衍生表达」，并给出该表达 + 中文释义 + 必要语境提示。

## 0. 一句话定位

「拓展」不是第二本词典，也不是无脑堆短语。它是一个**以权威词典/开源语料为底座、以统计与向量信号做召回过滤、以 LLM 做终判与生成**的候选表达发现管线。目标是：给定一个词条（如 `give`、`blast`），判断并输出类似 `given`（置于句首的非本意用法）、`have a blast`（与「爆炸」本意无关）这类**非字面可推导**的表达。

本文不强制绑定你的论文，但会指出哪些环节可以自然复用你已经掌握的检索/融合思路（见 §8）。

## 1. 问题定义

### 1.1 要识别什么

我们把「拓展」限定为四类（暂定，可按你确认后增减）：

| 标签 | 定义 | 示例 |
|------|------|------|
| `verb_form` | 动词变形后语义漂移，往往词性也变 | give → given（作介词/连词「鉴于」） |
| `idiom` | 惯用语/习语，整体义 ≠ 字面义组合 | have a blast；make ends meet |
| `slang` | 俚语/口语化固定表达 | spill the beans；kick the bucket |
| `special_colloc` | 特殊搭配，字面上勉强可猜但属高频固定搭配 | double-edged sword；a double-edged sword |
| `phrasal_verb` | 短语动词（可归入 verb_form 或单列） | give up / give in / give away |

> 说明：`phrasal_verb` 你之前已有 `reference_phrasal_verbs.json`（3217 条），它更适合作为**召回底库之一**，而不是被 AI 现场生造。最终「拓展」栏只保留**真正非字面、需要记忆**的那部分。

### 1.2 不要识别什么（负样本）

- 完全字面组合：`blue car`、`eat dinner`、`open the door`
- 语法正常、语义可组合、无固定性：`very good`、`go home`
- 语料库里已作为普通「搭配/短语」存在的普通表达（避免和现有列重复）

这就是「拓展」和「搭配/短语」的边界：**拓展=语义漂移/非组合性；搭配/短语=高频共现但语义可组合**。边界由语义漂移分数（§6.4）和结构启发式（§6.3）共同决定。

## 2. 资源调研全景

### 2.1 权威词典：理想与现实的差距

| 资源 | 权威性 | 开放程度 | 能否作为底座 | 结论 |
|------|--------|----------|--------------|------|
| **牛津 OALD / ODE** | 极高 | 无官方开放数据 | 否 | 只能通过个人本地 API/爬虫，有版权与合规风险 |
| **朗文 LDOCE** | 极高 | 无官方开放数据 | 否 | `ldoce-mcp-server` 等项目存在，但依赖抓取，合规存疑 |
| **柯林斯 COBUILD** | 高 | 部分网页可查 | 否 | 无稳定开放数据集 |
| **剑桥 CALD** | 高 | 网页可查 | 否 | `dictionary-crawler`(PyPI) 可爬，合规存疑 |

**结论**：牛津/朗文不能作为「开源可再分发」的底座，否则会污染你打算开源的项目。它们更适合放在**终端用户侧**：程序运行时由用户自己的 API/网络去查询，或作为「可选词典扩展包」由用户自行提供（见 §9 合规）。开源可发布的数据，必须用下面 §2.2 的开放资源。

### 2.2 可合法再分发的开放词典/数据集（底座首选）

1. **DANTE（dantedictionary.com / lexicalcomputing/dante）**
   - 规模：42,000 词目 + 23,000 多词表达 + 27,000 习语/短语。
   - 优势：结构化、开放、覆盖多词表达和习语，**最适合作为「拓展」主底座**。
   - 提供原始数据 + 查询 API。

2. **McGraw-Hill 习语包（processempathy/english-idioms）**
   - 规模：22,209 条表达，`phrases.json`。
   - 优势：习语覆盖好，可直接做召回底库。
   - 注意：许可为「个人/非商业使用」，**开源分发需确认许可**，否则只能作为本地增强、不随仓库分发。

3. **ECDICT（本地已有 `C:\KTRT\data\ecdict.csv`）**
   - 规模：约 77 万词条，含 phrase 字段。
   - 优势：已本地化，零网络成本，适合做**兜底召回**和词形/变体映射。

4. **你的短语动词库 `reference_phrasal_verbs.json`（3217 条）**
   - 作为 verb_form / phrasal_verb 的权威种子。

5. **牛津搭配词典的非官方移植（popbones/Dictionary.EnglishCollocation）**
   - 形式为 CHM 词典数据，内容本身版权敏感，**仅可用于个人本地校验，不可开源分发**。

### 2.3 学术文献（Google Scholar / 期刊）

围绕「非字面表达 / 习语识别 / 搭配提取」的核心文献与结论：

1. **Haagsma, Bos, Nissim 等（2019）《Casting a Wide Net: Robust Extraction of Potentially Idiomatic Expressions (PIE)》**
   - 这是最直接的理论基础：提出 **Potentially Idiomatic Expressions（PIE，潜在习语表达）** 概念——不追求「一定是习语」，而是「可能是习语，值得标注/记忆」。
   - 关键结论：**词典是可靠来源；把多部词典合并能显著提升召回**。
   - 指标：基于解析的抽取 F1 约 88%，多词典合并后 >92%。
   - 开源：代码 `hslh/pie-detection`，标注语料 `hslh/pie-annotation`（CC-BY-4.0）。
   - 借鉴点：我们的「拓展」本质就是「潜在非字面表达」，与 PIE 概念完全对齐。

2. **搭配提取统计方法（Firth 语境论 / Church & Hanks 1990 等）**
   - 核心统计量：互信息 MI、T-score、对数似然比 LLR、Dice 系数（公式见 §6.3）。
   - 借鉴点：用于**过滤透明组合**（低 MI 的字面搭配直接淘汰）。

3. **深度学习习语识别（MICE、BERT-based idiom identification、CLCL、mMERGE、PARSEME/DiMSUM）**
   - **MICE**：基于 BERT/ELMo 的上下文嵌入做习语检测，说明「上下文向量」是区分字面/非字面的有效信号。
   - **CLCL（Contrastive Learning + Curriculum Learning）**：用对比学习增强习语表征，适合我们做「语义漂移」排序。
   - **PARSEME / DiMSUM**：多语言动词多词表达（MWE）序列标注任务，提供标注范式（BIO 标签）。
   - 借鉴点：语义漂移分数（§6.4）本质上是「表达整体向量 vs 词项字面组合向量」的对比，正是 MICE/CLCL 思路的轻量复用。

4. **数据集**
   - **EPIE Corpus**：717 个习语、25,206 句，含字面/非字面上下文，适合做评测。
   - **VNC-Tokens / Gigaword / IDIX / SemEval-2013 Task 5b**：习语与 MWE 检测基准，可用作离线评测集。
   - 借鉴点：上线前用 EPIE/VNC 抽样做**精度回归**，量化「拓展」栏的误报率。

## 3. 算法总体设计（五阶段漏斗）

整体是一个**从宽到严的漏斗**：先高召回捞出候选，再逐层过滤/排序，最后用 LLM 做终判与生成。这样既利用开放资源的规模，又避免 LLM 凭空生造。

```
阶段0  词目归一 + 形态展开
  ↓
阶段1  统一表达库构建（多源合并）
  ↓
阶段2  召回（词形/lemma 倒排索引）
  ↓
阶段3  过滤（结构启发式 + 统计量）
  ↓
阶段4  语义漂移排序（向量距离）
  ↓
阶段5  LLM 终判 + 生成中文释义/例句（pro 模型）
```

### 阶段 0：词目归一与形态展开

- 输入词条：`word`（如 `give`、`blast`、`phenomenon`）。
- 用 ECDICT + 一个轻量词形还原器（如 `Lemminflect` / `spaCy` lemma）做：
  - **主词形**：`give` → lemma `give`
  - **变形集合**：`give` → {give, gives, gave, given, giving}
- 目的：让 `given`（句首用法）能命中词目 `give` 的「拓展」；让 `blast` 能命中 `have a blast`。

### 阶段 1：统一表达库构建（多源合并）

- 数据源优先级（高→低）：
  1. DANTE（多词表达 + 习语，结构化，权威）
  2. 你的 `reference_phrasal_verbs.json`（短语动词种子）
  3. McGraw-Hill idioms（习语，补充）
  4. ECDICT phrase 字段（兜底）
- 合并时统一为条目对象：
  ```json
  {
    "expr": "have a blast",
    "lemma_keys": ["have", "blast"],
    "tags": ["idiom"],
    "source": "dante|mcgrawhill|user|ecdict",
    "zh": "玩得很开心",
    "example": "..."
  }
  ```
- 去重策略：以 `lemma_keys` 排序后的键 + 归一化 expr（小写、去多余空格）做主键，同义不同源时**保留来源并加权**（多源命中可信度更高，呼应 PIE「多词典合并提升覆盖」）。

### 阶段 2：召回（倒排索引）

- 对表达库建立 `lemma → expr_id` 倒排索引。
- 输入词条的 `word` 及其变形集合，取并集去查倒排，得到候选表达集合。
- 这是**高召回**步骤，宁多勿漏。例：`blast` 召回 `have a blast`、`a blast from the past`、`at full blast` 等。

### 阶段 3：过滤（结构启发式 + 统计量）

目标是剔除「透明字面组合」。

**结构启发式：**
- 表达是否含封闭词类锚点（介词/冠词/连接词）？如 `in`、`of`、`a`、`to`。含锚点 → 更像固定表达。
- 表达整体长度 2–4 词为常见习语区间；过长的先降权。
- 表达是否跨词类（动词+名词+介词）且词性序列罕见？罕见序列更可能是习语。

**统计量（在有语料的源上计算，语料可用 Gigaword 子集 / BNC 子集 / 你的本地语料）：**

设 x、y 为表达中的两个成分词，N 为总 token 数，f(x)、f(y) 为词频，f(x,y) 为共现频：

- **互信息 MI**：`MI(x,y) = log2 [ f(x,y)·N / (f(x)·f(y)) ]`
  - MI 越高越固定；低 MI ≈ 独立共现，判为字面。
- **T-score**：`T(x,y) ≈ [ f(x,y) − f(x)f(y)/N ] / √(f(x,y))`
  - 兼顾频率与显著性，用于对高频字面组合降权。
- **对数似然比 LLR**：G² 检验，判断共现是否显著非独立。
- **Dice**：`Dice(x,y) = 2·f(x,y) / (f(x)+f(y))`
  - 简单、稳健的关联强度。

判定：若表达内所有相邻词对的 MI 都低于阈值（如 < 3）或 LLR 不显著，判为字面组合 → 淘汰。阈值作为可调参数。

### 阶段 4：语义漂移排序（向量距离）

这是「拓展」区别于普通搭配的核心信号。

- 定义**语义漂移**为：表达整体向量 vs 其成分词「字面组合向量」的差异。
  - `emb(expr)`：直接把整个表达当一个 token 送入句子向量模型（如 `all-MiniLM-L6-v2` / `BGE` / 若本地性能允许用更大模型）。
  - `emb_literal(expr)`：各成分词向量的组合（如加权平均，或按词性加权）。
  - `drift = 1 − cos_sim(emb(expr), emb_literal(expr))`
- **drift 越高 → 越非字面 → 越像「拓展」**。
  - `have a blast`：整体义「玩得开心」离 `have`+`blast` 字面很远 → 高 drift。
  - `eat dinner`：整体义 ≈ 字面组合 → 低 drift。
- 与阶段 3 的 MI/T-score 融合成一个综合分：
  `score = α·norm(drift) + β·norm(MI) + γ·source_weight`，α/β/γ 为可调权重。

> 这是对 MICE/CLCL 的轻量复用：MICE 用上下文嵌入区分字面/非字面，我们退化为「表达式级 vs 组合级」向量的距离，成本低、可本地化、无需标注训练。

### 阶段 5：LLM 终判 + 生成（pro 模型）

- 只把**通过阶段 3/4 的短名单**（每词 ≤ 8–10 条候选）交给 LLM，避免全量调用。
- Prompt 要求（结构化 JSON 输出）：
  - 判断每条候选是否真是「非字面衍生表达」；
  - 若是，给出：`zh`（地道中文释义）、`tag`（verb_form/idiom/slang/special_colloc/phrasal_verb）、`example`（含该表达的原句 + 中文翻译）、`register`（正式/口语/俚语）、`note`（可选语境提示）；
  - 若否，返回 `drop`。
- 只保留 LLM 判定为「是」的条目，并写回「拓展」栏。
- **模型分工**：此终判与生成用 **pro 模型**（保证质量）；大规模召回/过滤/向量计算用本地确定性算法（不占模型配额）。

## 4. 类型标签体系（算法输出维度）

每个「拓展」条目最终携带：

```json
{
  "word": "give",
  "expr": "given",
  "tag": "verb_form",
  "zh": "鉴于；考虑到（置于句首）",
  "example": "Given the circumstances, we should wait.",
  "example_zh": "鉴于当前情况，我们应该等待。",
  "register": "formal",
  "note": "given 置于句首时不再是 give 的过去分词本意"
}
```

标签判定优先用结构规则（如是否变形+句首/介词化），LLM 仅做纠偏与补充。

## 5. 数据流与落地架构

### 5.1 离线管线（脚本，非运行时）

- 一次性/可重复跑：
  1. 下载/校验 DANTE、McGraw-Hill（许可允许时）、ECDICT。
  2. 构建统一表达库（SQLite 或 JSON，存入 `C:\KTRT\data\`）。
  3. 对目标词书全量跑「召回→过滤→排序→LLM 终判」，生成「拓展」缓存。
  4. 结果回写 `words` 表新增列（如 `extension TEXT`），并重导出 Excel。

### 5.2 运行时（网页端展示）

- 背单词页「拓展」栏直接读缓存，不做实时计算。
- 「拓展」不参与朗读（中文不读，与你之前规则一致：只有英文/单词可 TTS）。
- 未来增量：用户导入新词书时，离线管线对新词重跑。

### 5.3 依赖建议（最小化）

- 词形还原：`Lemminflect` 或 `spaCy(en_core_web_sm)`（二选一）。
- 向量：`sentence-transformers` + 一个 MiniLM/BGE 小模型（本地离线）；若想更省事，可先用 API embeddings（见 §10 待确认）。
- 表格：`openpyxl` / `pandas`（已有）。
- 统计量：纯 `numpy`/标准库即可，不引入额外重依赖。

## 6. 版权与合规

- **开源可分发底座**：DANTE（确认其许可）+ ECDICT + 你的自有短语库。
- **不可开源分发**：McGraw-Hill（个人/非商业）、牛津搭配词典非官方移植、LDOCE/剑桥抓取结果。
  - 处理：把「拓展」的生成做成**可插拔数据源**；开源仓库只带合法底座，McGraw-Hill/牛津等作为「用户自备的可选增强包」，由用户本地放入数据目录，程序运行时加载（类似你之前的「词典做成可选下载项」思路）。
- **运行时联网查词典**：留给用户自己的 API/网络，程序不内嵌抓取、不代发请求，避免合规责任。
