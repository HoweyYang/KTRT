# 调研与创新路径（市场 / 竞品 / 学术 / 差异化）

> 日期：2026-08-18
> 用途：记录“智能拓展词典”的市场现状、可借鉴学术路径、创新点与差异化，为算法定方向。

## 1. 市场现状：系统级词典的缺口（印证用户观察）

### 1.1 苹果 iOS / macOS 内置词典确实“落后且不被重视”

经检索确认，用户“苹果词典很落后、不重视”的直觉成立：

- **系统词典数量少、格式封闭**：苹果原装词典用 XML + HTML 混合格式，XML 用于索引与显示控制；第三方词典只有 HTML、未适配 XML，导致**选中词弹窗体验很差**（FreeMdict 论坛 2025）。
- **macOS Dictionary.app 被批评**：被指“达不到好词典的标准”，且**只能查词、不能搜短语**——“词条里其实有短语释义，但没有办法搜索”（TidBITS 2025）。
- **Spotlight 查词被削弱**：iOS 18 下拉搜索不再直接显示单词释义，用户需重新勾选系统词典（V2EX 2024）。
- **iOS 无词典内容公开接口**：开发者反馈“iOS 上苹果没有提供获取词典内容的接口”（FreeMdict 论坛 2026）。

结论：系统级“选词即查”确实存在结构性缺口——**词典少、查短语弱、无开放接口、体验差**。这正是“智能拓展词典插件”可以切入的空间。

### 1.2 现有“词中心”产品（基线/竞品）

| 产品 | 形态 | 特点 | 局限（我们的机会） |
|------|------|------|---------------------|
| **沙拉查词 Saladict** | 浏览器扩展，开源 | 聚合大量词典、划词翻译、生词本、PDF | 本质是“多词典并列展示”，不是“以词为中心的关联爆炸”；仍偏“翻译/查词” |
| **欧路词典 Eudic** | 跨平台 App | 支持 MDX 词典、跨软件取词、扩展词库 | 词典仓库强，但“拓展”仍是词典条目堆叠，非语义关联 |
| **有道词典** | App/网页 | 堆积柯林斯/牛津/朗文 + 近反同根 | 用户明确判断：这是“堆积”不是创新点；同义词/反义词/同根我们已有 |
| **ai-vocab-agent** | 开源项目 | Agentic RAG + FAISS + 词根知识图谱星图 + SRS | 方向接近，但重点是“记忆闭环”，且偏重词根而非“生僻衍生表达” |
| **dsh-knowledge** | RAG 插件 | 分块、嵌入、混合检索、rerank | 通用知识库，不是“词知识模型” |
| **GoldenDict / Lingoes** | 桌面 | 多词典聚合 | 老牌查词，无智能关联 |

共同点：大家都在“聚合词典 + 查词”。**没有一家把“以词为中心的生僻含义/衍生表达/词源同族的语义关联爆炸”作为核心能力**。

## 2. 学术算法路径（可借鉴的当代工作）

### 2.1 潜在习语表达（PIE）

- Haagsma, Nissim, Bos 2019《Casting a Wide Net: Robust Extraction of Potentially Idiomatic Expressions》：多词典合并是习语的可靠来源，可把抽取 F1 从 88% 提到 >92%。
- 借鉴：用“潜在候选”而非“确定命中”的立场做召回与置信度分级。

### 2.2 词义归纳 / 生僻义（WSI）

- **CoKE**：用上下文化知识嵌入归纳一词多义。
- **超图词义归纳（UOY）**：用超图建模词共现的多维关系，突破普通图的二元关系局限。
- **稀有词表示（Semantic Bridging）**：用外部知识库为低频/未见词补语义，适合“生僻义”。
- 借鉴：把“生僻义项/引申义”当 WSI 子任务，用上下文聚类识别低频义。

### 2.3 词义漂移 / 语义变化（LSC）

- **Lexical Semantic Change Detection** 综述：Periti & Tahmasebi 2024、Kutuzov et al.、Cambridge NLP 2026 综述。
- 借鉴：把“本义 vs 衍生义”的差异量化为语义漂移信号，作为“拓展”的核心判据。

### 2.4 习语/多词表达检测（深度学习）

- MWE-UD 2024《Is Less More?》：数据质量对习语检测的影响大于数量。
- BERT 对习语性（idiomaticity）的敏感度研究：模型能区分习语与普通词，但对习语子类的组合性差异捕捉不足。
- 借鉴：说明“语义漂移 + 结构启发式”仍必要，不能只靠嵌入相似度。

### 2.5 词源知识图谱

- **Etytree**：基于 Wiktionary 的交互式词源图，可探索祖先/后代/同源词，跨语言。
- **unified-etymology-graph**：2270 万关系 / 660 万词 / 5529 语言（CC-BY-SA），含同源对、派生链、借词路径。
- **opengloss-dictionary**：910 万语义边（同义/反义/上下位/搭配/屈折）+ 词源路径（97.5% 条目）。
- 借鉴：这是“多语言可扩展”与“词源/同族”维度的现成底座。

### 2.6 知识图谱 + 检索增强（GraphRAG）

- **Microsoft GraphRAG**：实体/关系抽取 + 层次社区摘要 + 局部/全局检索，适合需要关系推理的查询。
- **混合向量 + 图检索**（NebulaGraph + Qdrant、Neo4j + Qdrant 等实现）：先向量召回，再图遍历做多跳推理。
- 借鉴：回答“mine 有什么生僻搭配/引申义”这类问题，需要“词 → 关系 → 表达”的多跳，而非纯关键词/向量匹配。

## 3. 创新点清单（真创新 vs 借鉴）

### 3.1 相对“现有词典/查词工具”的差异化

1. **从“词典条目堆叠”到“词知识模型”**：不是并列展示多本词典，而是把词义/搭配/短语/词源/同族融合成一张可推理的关系图。
2. **“拓展爆炸”作为一等公民**：以词为中心的、分类型的、带置信度与来源的关联展开，而非背词时临时搜索。
3. **多语言可扩展**：算法主体语言无关，替换底座 + 词形还原器即可（英语先行，法语验证）。
4. **插件化分发**：桌面 / 浏览器 / 移动 / 系统级，填补 iOS 系统词典的缺口。
5. **人性化与个性化**：置信度分级、可解释来源、语境化例句、结合用户反馈排序。

### 3.2 相对“LLM / 浏览器定向搜索”的差异化

用户的核心追问：既然 LLM 和浏览器都能定向搜索，为什么还要这个算法？

答案不是“搜得更准”（LLM 很强），而是“**搜得更快、更结构化、更可复用、更个性化、更离线、更可信**”：

| 维度 | LLM/浏览器一次性搜索 | 智能拓展词典 |
|------|----------------------|--------------|
| 响应 | 每次现算/现搜，慢 | 预计算 + 索引，秒级 |
| 结构 | 自然语言长文，难复用 | 结构化条目（表达/释义/例句/语域/来源） |
| 关联 | 单次问答，无记忆 | 持久词知识图，可多跳关联 |
| 个性化 | 无 | 结合熟悉/收藏/造句反馈 |
| 可信 | 可能幻觉、无来源 | 每条带来源与置信度 |
| 离线 | 需联网 | 底座本地化，离线可用 |
| 分发 | 依赖平台 | 可作为插件嵌入任意软件 |

即：**我们不做“更会说话的搜索引擎”，而做“装在你手边、随时可调用的词知识引擎”。**

## 4. 盈利与版权（后话，仅记录方向）

- 版权：开源底座（DANTE/ECDICT/词源图谱/自有短语库）可随项目分发；权威词典（牛津/朗文）只能做用户自备的可选增强包。
- 盈利潜力：差异化在于“词知识模型 + 插件分发 + 个性化数据”，可走“免费开源内核 + 增值服务/专业词库/多语言授权”路线，具体方案待后续专门讨论。
