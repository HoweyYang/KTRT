# 背景与上下文（本分支的“记忆起点”）

> 作用：这份文件是「拓展算法」独立分支的背景补充。开新对话时，把本文件当作上下文喂给助手，即可无缝接上，无需从头解释 KTRT 是什么、我们聊到哪了。

## 1. KTRT 是什么

**KTRT = Kill Time Recitation Tool**，开发者 HoweyYueng（Howey / 杨皓天）。

一句话：一个**本地优先、高自由度的背单词程序**，界面是网页应用（本机 127.0.0.1:8000 启动），数据存在本地 SQLite，支持导入自定义词书。

### 已经具备的能力（截至 2026-08-18）

- 默认词书：GRE必背（6519 词，42 List）；另处理过雅思真经、考研红宝书（用户后续手动导入）。
- 词卡字段：单词、音标、各词性中文释义、搭配、短语、同义词、反义词、同根词。
- 一页一词，List 划分，进度条；可标记熟悉/不熟悉/收藏，后台记录、可删减。
- AI 自定义造句：输入中文提示词，用当前单词生成句子并高亮目标词，每词最多存 3 句（含翻译）。
- TTS 朗读：默认 edge-tts（联网），只读英文/单词，不读中文；语言可扩展（未来法语）。
- 深色/浅色主题；管理页可按 book/list 折叠、搜索、按熟悉/不熟悉/收藏/已背/造句筛选。
- 导入格式兼容：完整扩展 Excel（多列）与纯单词/翻译的简单 Excel。
- 已开源：GitHub（HoweyYang/KTRT），README 有趣风格，含安装包 / 可选词典 / 教程文档。

### 核心设计理念（贯穿始终）

1. **用户自定义优先**：不是替用户决定背什么，而是给一个高自由度的“背词工作台”。
2. **本地优先、数据可迁移**：词典/词库本地化，用户自己掌控数据。
3. **差异化创新点 = 自定义造句**：市面背词软件没有“按我的提示词、用当前词造我想要的句子并收藏”的能力。

## 2. “拓展”算法讨论的来龙去脉

### 2.1 需求起点

用户提出：在词卡中加一栏「拓展」，针对某些单词的特殊搭配/俚语/特殊表达——**常见、但基于本意比较生僻的衍生表达**。

示例（用户给的，用于写算法思路，词书里不一定有）：
- `give → given` 放句首表示“鉴于”（不再是一般过去分词本意）
- `blast → have a blast`（与“爆炸”本意无关）
- `double-edged sword`、`make ends meet` 这类不一定出现在“固定搭配/短语”里的表达

### 2.2 关键约束（用户明确）

- 不是每个词都要有「拓展」，命不中就留空，不硬凑。
- 需要一套**算法 + 资源检索范围/库**来为几千个词做匹配，算法逻辑储存在后台。
- 判定机制比较烧脑：动词及其变形（变形后词性可能变）、名词（怎么判定不明确）。
- 朗读只读英文，不读中文。
- 词库里的语料重复问题暂不考虑（如某词的名词和它本身都在语料库）。

### 2.3 第一版算法设计（用户“比较满意”）

初版《拓展栏算法设计.md》提出了核心定位与流程：

> 「拓展」不是第二本词典，也不是无脑堆短语。它是一个**以权威词典/开源语料为底座、以统计与向量信号做召回过滤、以 LLM 做终判与生成**的候选表达发现管线。

- 借鉴用户论文 HNSWPQ 的“级联检索”思想：`HNSW 图召回 → PQ 量化 → ADC 非对称距离 → 粗排/重排`，平移到 `词形召回 → 规则过滤 → 语义精排 → LLM 判定生成`。
- 五阶段漏斗：`词目归一+形态展开 → 统一表达库 → 倒排召回 → 结构/统计过滤 → 语义漂移排序 → LLM 终判`。
- 语义漂移 = “表达整体向量 vs 字面组合向量”的距离（对 MICE/CLCL 的轻量复用）。
- 底座资源：DANTE + ECDICT + 用户短语库；McGraw-Hill/牛津/朗文仅作本地可选增强（版权原因）。

## 3. 用户本轮“mindstorm”（新思路，重要）

用户补充了四条，把讨论从“词卡的一栏”提升到“独立算法/产品”的高度：

1. **模型选择暂不绑定**：现阶段不决定模型厂商，也不默认用 DeepSeek（原文档 §8 需修正为“可配置/待定”）。
2. **呈现形态 = 插件**：手机/电脑插件、针对软件的系统级插件。用户观察到苹果 iOS 自带词典“很落后、不重视”（后经检索证实：系统词典少、第三方只能 HTML 适配差、iOS 无词典内容 API、Spotlight 查词被砍）。
3. **算法内容要多路径探索**：结合我们的讨论、当代知名算法、用户水论文（HNSWPQ）的算法，放开思维，找创新点，想要一个“更人性化、自己的算法”。
4. **明确算法的意义与差异点**：语言是人创造的，任何表达定向搜索都能搜到；算法**不是创造新表达，而是服务定向检索**。但 LLM/浏览器也能定向搜索，所以必须找到不同点。用户的定位是——**“智能拓展词典”**：以单个词为中心的差异化“爆炸”，一个类似插件的存在，给备考/语言专业人士做**极致检索关联**，而非背词时临时去搜。可扩展到其他语言/方言（目前只做英语，法语是下一步）。

用户引用并认可的差异化定义（来自初版）：

> 「拓展」不是第二本词典……是候选表达发现管线。

## 4. 本分支的目的与边界

- **目的**：继续研究“拓展/智能拓展词典”算法，暂不动工实现。
- **当前状态**：调研 + 思路整理 + 算法设计扩展，等用户确认后再进入实现。
- **不做**：现在不写实现代码、不跑批处理、不绑定模型厂商。
